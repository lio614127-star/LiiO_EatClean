# Plan 28-01: AI Rebalance Data & Service Layer

Objective: Establish the data foundation and AI orchestration logic for proactive meal rebalancing.

## Proposed Changes

### Data Layer
- **[NEW] CoreData Model Version 8**:
    - `DailyPlan`: Add `isRebalanced` (Bool), `rebalanceReason` (String), `rebalancedAt` (Date), `previousPlanSnapshot` (Binary Data).
    - `PlannedMeal`: Add `isLocked` (Bool).
- **[MODIFY] DailyPlanRepository.swift**:
    - Update `savePlan` to handle new rebalance fields.
    - Add `lockMeal(id: UUID, locked: Bool)` method.
- **[MODIFY] DailyPlanModel.swift**:
    - Reflect CoreData changes in the struct.

### AI Service Layer
- **[NEW] AIRebalanceService.swift**:
    - Orchestrates context building for rebalancing.
    - Methods:
        - `checkRebalanceNeeded(record: DailyNutritionRecord) -> RebalanceTrigger?`
        - `requestRebalance(record: DailyNutritionRecord, preference: RebalancePreference) async throws -> RebalanceResult`
- **[MODIFY] AIOrchestrator.swift**:
    - Add `generateRebalancePlan(context: String) async throws -> RebalanceResult`.
    - Implement a specialized prompt with JSON schema enforcement for Rebalance.

## Verification Plan

### Automated Tests
- `DailyPlanRepositoryTests`: Verify saving and fetching rebalance metadata.
- `AIRebalanceServiceTests`: Mock AI responses and verify prompt construction.

### Manual Verification
- Check CoreData inspector to confirm entity migration.
